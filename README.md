# Отчет

## Что нашёл

### Долгая загрузка страницы

В vite.config.js параметр assetsInlineLimit был равен 10 МБ.
Из-за этого крупные картинки попадали прямо в JavaScript,
а основной файл после добавления Special offers весил около
52 МБ. Браузеру приходилось загружать его перед запуском
приложения. Считаю это одной из самых критичных проблем.

При проверке через npm run preview с отключённым кешем
и ограничением Slow 4G страница оставалась пустой примерно
4,4 минуты. На тот момент было передано около 48 МБ.

### Лишние запросы данных

В App.svelte список квартир загружался трижды по разным
адресам, хотя использовался один и тот же JSON размером
около 16 МБ.

При старте также запрашивались подробности всех квартир.
Цены запрашивались каждые две секунды, даже если предыдущий
запрос ещё не завершился. На медленном соединении запросы
накапливались в очереди.

Поиск квартиры повторно скачивал список при каждом
изменении текста.

### Рывки при прокрутке

На первом экране видео перематывалось при каждом событии
прокрутки. Одновременно обработчик измерял и сдвигал строки
каталога и другие элементы ниже экрана, хотя пользователь
их ещё не видел.

### Лишние вычисления

Ипотечный калькулятор строил полные помесячные графики
ради получения одного ежемесячного платежа.

Галерея продолжала автоматически переключаться, когда
пользователь уже прокрутил её или открыл другую вкладку.

## Что исправил

Уменьшил assetsInlineLimit с 10 МБ до 4 КБ. Крупные изображения и шрифты теперь загружаются отдельно от кода.
Оставил одну загрузку списка квартир для каталога
и ипотечного калькулятора.
Убрал загрузку подробностей всех квартир при старте.
Подробности загружаются при открытии конкретной квартиры.
Заменил постоянные запросы цен одной загрузкой, в задании используются статические JSON-файлы.
Поиск теперь использует уже загруженный список квартир.
Убрал предварительный расчёт всех вариантов ипотеки, результат которого не использовался в интерфейсе.
В калькуляторе заменил построение помесячного графика прямым расчётом платежа через существующую monthlyPayment.
Добавил проверку видимости галереи и вкладки перед автоматическим переключением слайдов.
Исправил viewport: вместо фиксированных 1200 px используется ширина устройства.
Убрал двойной отступ между галереей и Special offers.

Для первого экрана:

Перенёс обработку событий прокрутки в requestAnimationFrame.
Новая перемотка видео не начинается, пока не закончилась предыдущая; после её завершения проверяется последнее нужное положение.
Пока не пройден закреплённый первый экран, обработчик пропускает измерения нижних секций и строк каталога.
Перевёл движение фона с top на transform.

Видео и его связь с прокруткой сохранены.

### Проверка в браузере

В Network при загрузке страницы виден один запрос flats.json.
Без ограничения скорости отображаются четыре предложения и каталог из 640 квартир.
После изменения assetsInlineLimit на Slow 4G стал
появляться текст, но изображения всё еще загружаются долго.
После изменений обработчика первый экран при визуальной проверке стал прокручиваться плавнее. Численные замеры FPS не проводил.
Сборка после изменений запросов завершилась успешно.
Последние изменения обработчика прокрутки проверялна сервере разработки.

Быстрая загрузка без ограничения скорости не означает,
что проблема медленного мобильного интернета полностью
решена.

## Что сделал бы дальше

Уменьшил фотографии и перевёл их в WebP. Сейчас многие изображения весят по 4–6 МБ.
Исправил фиксированную минимальную ширину остальных
секций и проверил страницу на телефоне.
Повторил замеры на Slow 4G в одинаковых условиях и проверил окончательную сборку

# Larch Quay

Landing page for the Larch Quay residential quarter.

## Requirements

- Node 24

## Setup

```
npm install
```

## Commands

- `npm run dev` starts the dev server on http://localhost:5173
- `npm run build` creates a production build in `dist`
- `npm run preview` serves the production build on http://localhost:4173
